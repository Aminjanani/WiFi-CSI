# What DensePose and RuView establish for this experiment

The engineering question is whether one router-to-ESP32 link can distinguish an empty bedroom, one occupant and two occupants on another day. An especially revealing pair of trials is one person walking versus two people sitting still. A system that consistently assigns the larger count to the walker has learned motion strength. More training windows from those same trials would reinforce the error.

## 01 · Read the paper against its experimental protocol

The supplied PDF is Geng, Huang and De la Torre's *DensePose From WiFi*, arXiv v1. The second web link is a project overview. Its description of full-body 3D motion capture goes beyond the experiment in the PDF. The paper predicts image-plane person boxes, keypoints and correspondence to a canonical body surface. It lists predicting 3D body shape as future work. A coordinate on someone's canonical forearm and a coordinate in meters from a bedroom wall answer different questions. [Paper, especially §§3–5](https://arxiv.org/pdf/2301.00250v1) · [Project overview](https://www.opensourceprojects.dev/post/9c36ba1a-fc67-4ba2-b42a-8711cc91c2f6)

**What the antennas measured.** Three transmitting and three receiving antennas supplied nine link measurements on each of 30 subcarriers at 100 Hz. Five consecutive samples matched one 20 FPS video frame. Each amplitude or phase input contained 1,350 values. A link samples reflections across the scene. Even in the paper, an antenna-pair index has no direct correspondence to a patch of floor. Our single link has fewer spatial observations and a nominal stimulus rate around ten pings per second. Duplicating a tensor along an antenna dimension would only duplicate information. [Paper, Fig. 2 and §§3, 3.2](https://arxiv.org/pdf/2301.00250v1)

**Where the spatial supervision came from.** The authors unwrapped, filtered and detrended phase, encoded amplitude and phase separately, fused them and learned an image-like representation. A region-proposal network with DensePose and keypoint heads then estimated people and surfaces. During training, pretrained image models supplied pseudo-labels from synchronized RGB, and a teacher supplied intermediate feature targets. Teacher misses and errors can propagate into training and scoring. A session labeled “two people” provides enough supervision for count classification, while conveying no information about which person is at the desk. [Paper, Figs. 3–7 and §§3.1–4.1](https://arxiv.org/pdf/2301.00250v1)

**Which result survives a change of layout?** Sixteen captures of about 13 minutes each covered six office and ten classroom arrangements, eight participants overall, and one to five people per capture as described. The same-layout protocol randomly split samples 80/20 with shared people and backgrounds. Neighboring frames can be very similar. The harder protocol withheld one classroom layout and trained on the other fifteen. One held-out layout gives little information about variation between new rooms. [Paper, §§4.1–4.2](https://arxiv.org/pdf/2301.00250v1)

| Paper metric | Same layout | Held-out layout | Interpretation for counting |
|---|---:|---:|---|
| Person bounding-box AP | 43.5 | 27.3 | Localization quality varies substantially with layout. |
| Person box AP at IoU 0.50 | 87.2 | 51.8 | A loose spatial matching criterion. Reading 87.2 as percent correct headcounts changes the metric. |
| Dense correspondence AP using GPS | 45.3 | 25.4 | Scores locations on a body surface. It gives no empty-room false alarm rate. |

Values are from Tables 1–3 and 7–8. The same-layout image baseline scored 84.7 box AP. Some entries in v1 differ between tables and prose, including box AP at IoU 0.75 in Table 1 and the paragraph below it. Use the named table and metric when quoting. False occupants in an empty bedroom, missed stationary people and confusion between one and two require directly labeled count trials. [Paper, pp. 7–9](https://arxiv.org/pdf/2301.00250v1)

**What to borrow for a neural baseline.** Table 5 moves from 39.5 to 40.3 box AP with sanitized phase, to 42.9 with auxiliary keypoint supervision, and to 43.5 with transfer learning. Transfer also reduces iterations from 186,000 to 145,000 in that comparison. Figure 8 identifies rare poses and crowded scenes as failure cases. Preserve raw complex samples now so that phase or temporal structure can be tested later. For our count-only task, first compare a small 1D temporal CNN using aligned per-subcarrier amplitude to the forest on identical held-out recordings. Add calibrated phase in a separate experiment, fit preprocessing on training blocks only and report whether it improves errors for still people. [Paper, Tables 5–6 and §4.8](https://arxiv.org/pdf/2301.00250v1)

## 02 · Trace RuView from receiver to evidence

This review follows the collection, inference and evaluation paths relevant to the bedroom experiment at revision `13b47883a73d5070f35a3f04aec2ffa778b47e29`. The linked hardware results are the maintainers' reports. [Reviewed source revision](https://github.com/ruvnet/RuView/tree/13b47883a73d5070f35a3f04aec2ffa778b47e29)

| Component examined | What the implementation or measurement establishes | Decision for this repository |
|---|---|---|
| ESP32 CSI collector | Serializes receiver metadata, handles different radio packet formats, marks invalid first-word sanitation, and carries synchronization information on supported paths. Transport and preprocessing choices affect which bytes reach the model. [Collector source](https://github.com/ruvnet/RuView/blob/13b47883a73d5070f35a3f04aec2ffa778b47e29/firmware/esp32-csi-node/main/csi_collector.c) | Keep the raw bytes and validity flag. Use a known LLTF configuration, filter for the AP, preserve sequence and device time, and test packet continuity. |
| Edge count and server | ADR 346 describes a bounded subcarrier-diversity heuristic under a debounced presence decision. It documents nodes emitting absent with a positive count. Gating removes that contradiction, but a missed presence can then erase a real count. [Design decision](https://github.com/ruvnet/RuView/blob/13b47883a73d5070f35a3f04aec2ffa778b47e29/docs/adr/ADR-346-fail-closed-edge-occupancy-evidence.md) | Learn counts from independent operator labels. Derive presence from count. Keep packet loss and unknown results distinct from zero. |
| Physical C6 qualification | Across a five-minute run, 61 packets on the updated node reported absence and none paired absence with a positive count. The test assessed message consistency. The room had no independent headcount labels during that run. [Hardware record](https://github.com/ruvnet/RuView/blob/13b47883a73d5070f35a3f04aec2ffa778b47e29/docs/validation/2026-08-31-esp32-c6-occupancy-integrity.md) | Verify the whole chain using a human-declared count, especially when the estimate is wrong but internally consistent. |
| Sensing server and occupancy benchmark | The server carries evidence tied to calibration and source. The benchmark consumes supplied truth and predictions, checks subject/environment overlap, distinguishes synthetic provenance and checks class coverage. A scorer can validate an evaluation design without producing measured performance. [Server source](https://github.com/ruvnet/RuView/blob/13b47883a73d5070f35a3f04aec2ffa778b47e29/v2/crates/wifi-densepose-sensing-server/src/main.rs) · [Benchmark source](https://github.com/ruvnet/RuView/blob/13b47883a73d5070f35a3f04aec2ffa778b47e29/v2/crates/wifi-densepose-train/src/occupancy_bench.rs) | Label the pilot as a same-room, different-day experiment. An eventual claim about new people or rooms needs those held out separately. |

**The pretraining metric answers a different question.** The published card retracts an earlier presence headline from a recording containing 6,062 present labels out of 6,063 frames. The replacement 82.3% metric measures whether the representation puts temporally close samples closer than distant samples. A receiver can recognize a drift in its radio environment while still confusing two motionless people with an empty room. Likewise, the repo's deterministic DSP proof uses a labeled synthetic reference, which makes it suitable for regression checks. Neither experiment provides a 0/1/2 accuracy figure for this installation. [Model card](https://github.com/ruvnet/RuView/blob/13b47883a73d5070f35a3f04aec2ffa778b47e29/docs/huggingface/MODEL_CARD.md) · [DSP proof](https://github.com/ruvnet/RuView/blob/13b47883a73d5070f35a3f04aec2ffa778b47e29/docs/proof-of-capabilities.md)

**A real failure mode worth reproducing as a control.** RuView's November presence beta reported promising held-out results on a C6. Its November 11 correction explains that changing occupancy also changed the mixture of transmitters and traffic. The keyboard/mouse label further coupled occupied trials to active computer use. The authors withdrew reliance on those accuracy figures. In our bedroom, leave the laptop and router running during empty recordings, maintain the same probing schedule, include occupied trials with nobody touching the laptop, and inspect whether an RSSI-only model performs as well as CSI. The existing AP filter helps, but AP traffic can still change with room activity. [Corrected release](https://github.com/ruvnet/RuView/releases/tag/v0.9.5-presence-evidence-beta.1)

## 03 · Public datasets

| Resource | What can transfer | How to use it |
|---|---|---|
| WiCount, from the CSI-BERT2 authors | Meeting-room recordings labeled 0–3, ESP32-S3, one transmitter and several receivers, 20 MHz, 52 complex subcarriers. The card describes roughly 100 Hz collection and sampling-rate transfer experiments. [Author dataset card](https://huggingface.co/datasets/RS2002/WiCount) | Closest match in target. Use classes 0/1/2 for a separate external benchmark. Build an explicit adapter for byte convention, occupied-bin mapping, packet cadence and link identity. Keep simultaneous receiver recordings from a trial together. Test external-only, bedroom-only and combined training on the same reserved bedroom day. |
| RadioPoints crowd counting | Labels 0–7 across three rooms with an Intel 5300 receiver. Authors permit attributed noncommercial research. [Authors' data and terms](https://github.com/RadioPoints/Device-free_RF_Human_Sensing_Datasets) | Useful for reproducing a counting feature or challenging layout dependence. Different hardware, driver and file structure require their own parser. |
| ESP32 person-presence dataset | Small single-room collection with empty, present, moving and unlabeled records. [Authors' dataset](https://data.mendeley.com/datasets/zycty7ksky/1) | Can exercise a binary presence experiment. “Moving” describes activity and supplies no exact headcount. |

RuView's model artifacts, demo streams and evaluation fixtures have different purposes. In the reviewed paths I did not find a drop-in set of independently labeled 0/1/2 trials matching a classic ESP32 receiver, an ordinary AP and this room. For external data record the source, allowed uses, original trial IDs, receiver, radio settings and label meanings before combining features. Treat the bedroom holdout as the deployment test.

## 04 · What would justify the next investment?

1. **Measure the link.** Repeat empty and occupied runs with the same traffic. Check valid packet rate, timing gaps, oversized packets and how many windows survive by class. If empty trials disproportionately disappear, accuracy on accepted windows alone can look impressive.
2. **Measure the first model.** On a preselected new day, compare the majority, RSSI-only and full-CSI results. Inspect quiet single-person misses, empty-room false alarms and 1↔2 confusion. Report the number of sessions and usable windows per class, the errors per session and per-day variation. Decide acceptable error rates with the eventual dashboard user.
3. **Buy spatial information only if it helps.** A second receiver is worth testing when a stable link repeatedly misses a position. Measure both links on the same trials, align windows, then compare each link to fusion. Two receivers can still observe similar reflections. Treat every claimed gain as an empirical question.
4. **Add labels before adding dashboard outputs.** A count model needs a count per interval. A zone model needs known zone labels. Per-person activity requires identity-free trial annotations that say which activity occurred in which zone at the same time. Start with a single person and coarse motion. Ask whether matched still/speaking and silent/gesturing trials remain separable before displaying “talking.”
